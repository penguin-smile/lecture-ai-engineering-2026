# 第4回 解答

## 宿題

* **取り組んだレベル**：基礎
* **やったこと**：同じ評価ラベル（`lectures/04/labels.jsonl`）に対して、採点モデル（`AIE_MODEL`）をデフォルトの `gemini-3.5-flash-lite` から `gemini-3.5-flash` に変更して `uv run python -m app.judge` を再実行し、基準別の一致率と要確認の件数の変化を比較した。
* **結果（変更前 `gemini-3.5-flash-lite` → 変更後 `gemini-3.5-flash`）**
  * **基準別の一致率**
    * 根拠：7/9 → 7/9（要確認 1 → 1）
    * 範囲：9/10 → 9/10
    * ヒント：9/10 → 9/10
    * 分かりやすさ：9/10 → 9/10
    * 回の表示（コード）：7/10 → 7/10
  * **総合の一致率**：5/9（coverage 90%） → 5/9（coverage 90%）
  * **要確認の件数**：1件（#05 根拠） → 1件（#05 根拠）
* **気づき・疑問**
  * 採点モデルを上位の `gemini-3.5-flash` に変更しても、各基準の判定（pass / fail / unsure）および一致率・要確認件数はすべて同一であり、変化は見られなかった。`temperature=0` と `rubric.md` の明文化された基準により、モデルのサイズに関わらず一貫した判定が行われることが確認できた（一方で、出力される判定理由の文章は `gemini-3.5-flash` の方が参照内容に即してより具体的に記述されていた）。また、モデルを変えても #05 の「根拠」が同様に `unsure` となったことから、境界ケースの判定を確定させるにはモデル変更ではなく `rubric.md` のルール追記が必要であることが分かった。
